# 리스크 검토 이관 설계

## 목적

리스크 관리는 AI 분석 결과를 분류·심각도 결정 후 이관하는 곳으로 마무리한다. 리스크 검토는 이관된 사안을 회사의 대응 논리, 검토 답변, 증빙으로 관리하는 별도 기록 공간으로 만든다.

## 식별자와 원본 보존

- 업무용 리스크 ID는 원본 `Risk.risk_code`를 사용한다. 형식은 기존 규칙인 `AS|LI|EQ|SA|CO_YYYYMMDD_NNN`만 사용한다.
- UUID는 API 관계와 DB 내부 식별자로만 유지하며, 리스크 검토 화면에는 표시하지 않는다.
- 이관 시 원본 Risk와 RiskPackage의 내용을 스냅샷으로 복사한 `RiskReviewCase`를 만든다. 이후 원본 분석이 바뀌어도 이관 시점의 검토 근거는 변하지 않는다.
- 원본 Risk는 DB에 보존하되 `RISK_TRANSFERRED` 이력으로 표시하고, 리스크 관리·설정 관리·일반 리스크 목록에서는 숨긴다.

## 이관 규칙

- 리스크 관리 상세에서 사용자가 검토 분류(Check/Pending/Pass)와 심각도(High/Medium/Low)를 명시적으로 선택한 뒤에만 `이관` 버튼을 활성화한다.
- Pass는 이관 대상이 아니다. Check 또는 Pending인 경우만 이관할 수 있다.
- 같은 원본 Risk는 한 번만 이관할 수 있다. 재클릭은 기존 검토 건을 반환하여 중복 복사를 막는다.

## 리스크 검토 데이터와 화면

- 리스크 검토 목록은 `RiskReviewCase`만 조회한다. 각 행에는 업무용 리스크 ID, 제목, 심각도, 검토 분류, 이관 일시, 진행 상태를 보인다.
- 상세 화면은 이관 당시 원본 분석(종합 판단·사건 추론·감사 이슈·기준서 근거·원장 근거), 검토 질문, 권장 증빙을 읽기 전용으로 유지한다.
- 각 검토 질문에 담당자가 텍스트 답변을 입력하고 저장한다. 저장은 질문별로 즉시 DB에 반영한다.
- 검토 건의 심각도와 검토 분류도 선택 즉시 DB에 반영한다. 검토 탭에서 Pass로 바꾸면 기본 목록에서는 숨기되 데이터와 직접 URL은 보존한다.

## 증빙 첨부

- 각 검토 건에 최대 10개의 증빙 파일을 첨부할 수 있다.
- 파일은 `RiskReviewAttachment` 레코드로 검토 건에 귀속하고, 파일명·콘텐츠 타입·크기·파일 바이트와 등록 일시를 함께 보관한다.
- 업로드 전 현재 첨부 수를 확인해 10개 초과 요청은 거절한다. 각 파일은 목록에서 내려받거나 삭제할 수 있다.

## 오류와 검증

- 존재하지 않는 원본/검토 건은 404, 미선택 분류·심각도 또는 Pass 이관은 422, 중복 이관은 기존 건 반환으로 처리한다.
- 서버는 회사 소속 검증을 수행한다.
- 테스트는 ID 보존, 이관 복사·목록 은닉·중복 방지, 질문 답변 저장, 분류/심각도 즉시 변경, 10개 첨부 제한을 포함한다.
